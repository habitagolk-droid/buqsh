# تقرير تطوير محفظة العملات الثلاث

**المشروع:** بُقش  
**التاريخ:** 13 أكتوبر 2026  
**الحالة:** نموذج واجهة أولي، وليس محفظة مكتملة أو متصلة بخدمة مالية.

## نطاق التقرير

يتناول هذا التقرير محفظة العملات الثلاث فقط:

- الريال اليمني `YER`، الرمز `﷼`.
- الدولار الأمريكي `USD`، الرمز `$`.
- الريال السعودي `SAR`، الرمز `ر.س`.

## ما تم بناؤه

- نموذج `WalletModel` في `lib/models/wallet_model.dart` لتمثيل رمز العملة واسمها والرصيد الحالي والرصيد المعلّق والقيمة المكافئة للعملة الأساسية وحالة المحفظة الافتراضية، مع دعم JSON.
- واجهة قائمة المحافظ في `lib/screens/wallets/wallets_screen.dart` تعرض المحافظ الثلاث، وتنسّق الرصيد بحسب رمز العملة، وتستخدم لونًا مختلفًا لكل عملة.
- بيانات العرض الحالية داخل الشاشة:

| العملة | الرصيد التجريبي | الحالة |
| --- | ---: | --- |
| YER | 0 | افتراضية |
| USD | 50,030 | القيمة الأساسية المسجلة: 26,515,900 |
| SAR | 0 | غير افتراضية |

- مزوّد أولي في `lib/providers/wallet_provider.dart` يحتوي على قائمة المحافظ وحالة التحميل والخطأ وإمكانية تحديد المحفظة الافتراضية.
- شاشة أولية لتفاصيل محفظة في `lib/screens/wallet/wallet_detail_screen.dart`.

## ما يعمل حاليًا وما لا يعمل

القائمة تعرض تصميمًا وبيانات ثابتة مكتوبة داخل الشاشة. لا تُحمّل المحافظ من API أو قاعدة بيانات، ولا تستخدم `WalletProvider` لعرض هذه البيانات. بطاقات العملات ليست تفاعلية ولا تفتح شاشة التفاصيل. شاشة التفاصيل نفسها تعرض حركات ومؤشرات تجريبية غير مرتبطة بمحفظة فعلية.

لا توجد حاليًا عمليات مالية فعلية، أو تحديث للأرصدة، أو أسعار صرف، أو تحويل بين العملات. القيمة المكافئة المسجلة للدولار ليست ناتجة عن عملية صرف موثقة داخل التطبيق؛ يجب تحديد العملة الأساسية ومصدر السعر قبل اعتمادها.

## المتبقي لإكمال المحفظة

1. تحديد العملة الأساسية، ومصدر أسعار الصرف، وقواعد الرسوم والتقريب.
2. جلب المحافظ وأرصدتها من API موثق، وربط النتائج بـ`WalletProvider` مع حالات التحميل والخطأ والفراغ.
3. ربط كل بطاقة بتفاصيل المحفظة نفسها وسجل حركاتها.
4. تنفيذ تغيير المحفظة الافتراضية وحفظه والتحقق من نجاح مزامنته.
5. تنفيذ التحويل بين YER وUSD وSAR مع إظهار سعر الصرف والرسوم والمبلغ المستلم قبل التأكيد.
6. ربط الإيداع والسحب والحركات بالعملة المحددة، وتحديث الرصيد بعد نتيجة الخادم فقط.
7. اختبار قراءة بيانات المحافظ والحسابات والتحويل والتقريب وحالات الفشل.
8. التحقق من عرض العملات الثلاث وسلوكها على جهاز Android بعد نجاح البناء.

## معيار اعتبار المحفظة مكتملة

تُعد المحفظة مكتملة عندما تُحمّل أرصدة العملات الثلاث من مصدر موثوق، وتعرض تفاصيل كل محفظة وحركاتها، وتنفذ التحويلات وفق أسعار ورسوم معتمدة، وتحفظ المحفظة الافتراضية، وتجتاز الاختبارات والتحقق على جهاز Android.
